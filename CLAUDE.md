# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Static site for **Protezione Civile ANA Casale Monferrato**, served via GitHub Pages at `pcanacasale.com` (see `CNAME`). No build system, no package manager, no bundler — every page is a self-contained HTML file (inline `<style>` and mostly-inline `<script>`) or a plain `.js` file loaded via `<script src>`. Deploys happen by pushing/uploading files directly to `main`; there is nothing to compile.

There is no test suite, linter, or dev server configured. To check a change, open the relevant HTML file directly in a browser (or serve the folder with any static file server) and exercise the feature manually.

## Repository layout

- `index.html` — public marketing site (chi siamo, attività, galleria, contatti).
- `area-riservata.html` + `area-riservata.js` — the reserved-area web app for volunteers (see below). `area-riservata.js` is a large (~8.5k line) monolithic script; grep for the function or panel name you need rather than reading it top to bottom.
- `scheda-volontario.js` — finestra della scheda volontario (prefisso `sv*`): schede Dati (con taglie DPI), Documenti, Visita medica, Formazione, Abilitazioni, Attestati, Interventi, regole "Da sistemare" usate anche dall'elenco Volontari e dalla dashboard.
- `archivio-volontario.js` — sezione "Archivio documenti" (prefisso `arc*`): attestati e documenti del volontario archiviati su Google Drive (`volontari.drive_folder_id`, sottocartelle Attestati e Documenti), in sola lettura. gli attestati dei corsi fissi (4 ore, 12 ore, Caposquadra, DAE) si riconoscono dalle parole chiave di `formazione_catalogo` (`arcCorsoDi`; `ARC_CORSI` solo se il catalogo manca; stessa regola nell'import della Edge Function), che vanno in Formazione sotto il corso (una volta sola, con data e scadenza unite da Drive, `formazione_registro` e campi del volontario: `svRenderCorsi()`); i file "Abilitazione - …" e le abilitazioni del registro nella scheda Abilitazioni; gli altri attestati nella scheda Attestati, la cartella Documenti in fondo a Documenti (`svRenderDrive()` in scheda-volontario.js, permesso `documenti_volontari` oppure `volontari`); stessa divisione nelle card della scheda personale (`arcRenderPersonale`). Tutto passa dalla Edge Function `archivio-volontario` (token della sessione; staff con `ho_permesso('documenti_volontari')` o `ho_permesso('volontari')` o il volontario stesso via `mio_volontario_id()`; secret `GOOGLE_SA_JSON`), che controlla che il file stia nella cartella del volontario e registra ogni apertura in `log_attivita`. Il PDF si apre da blob, mai link diretti a Drive.
- `allerta-home.js` — card "Stato allerta" in Home (prefisso `al*`), solo lettura: legge `allerta_cache`, che la Edge Function `allerta-arpa` riempie dal CAP-XML di ARPA Piemonte (zona Piem-I).
- `editor-pdf.js` — pagina Editor PDF (prefisso `ep*`, permessi `editor_pdf` per il livello base e `editor_pdf_completo`, ricontrollati in `editor-pdf-firma`): il PDF si modifica nel browser, sul server vanno solo modelli e PDF in firma tramite la Edge Function `editor-pdf-firma`, che verifica il token della sessione. `firma.html` è la pagina pubblica di firma a distanza.
- `formazione.js` — pagine Visite mediche e Formazione in Amministrazione (prefisso `fz*`, permessi `visite` e `formazione`): il registro sta in `formazione_registro` (`supabase/formazione_registro.sql`) e i corsi fissi vengono ricopiati nei campi di `volontari`. Ogni riga è collegata a una voce di `formazione_catalogo` (`supabase/formazione_catalogo.sql`): la assegna il trigger `formazione_registro_catalogo` (codice dei corsi fissi, poi parole chiave con `formazione_voce()`, abilitazioni non riconosciute in `DA_VERIFICARE`), che segna anche `aggiornamento` e calcola la scadenza vuota da `validita_anni`. La pagina raggruppa per voce; il pulsante Catalogo gestisce le voci (mai cancellate: disattivate o unite con `unita_in`). `arcVoce()` in archivio-volontario.js ripete la stessa regola nel browser: se cambia una, va cambiata anche l'altra.
- `convocazioni.js` — Generatore convocazioni in Strumenti (prefisso `cv*`, permessi `convocazioni` e `convocazioni_gestione`): PDF creato nel browser con pdf-lib, liste e storico passano dalla funzione SQL `conv_api` (`supabase/convocazioni.sql`), che riconosce l'utente dal token della sessione.
- `eventi.js` — pagina Eventi in Strumenti (prefisso `ev*`, permesso `eventi`): esercitazioni ed emergenze con squadra, mezzi e segnalazioni (`eventi`, `evento_volontari`, `evento_mezzi`, `evento_segnalazioni`), foto nel bucket privato `eventi`. A fine evento crea il record in `interventi` e `intervento_volontari`, contando solo i presenti.
- `eventi-polo.js` — seconda parte della pagina Eventi (stesso prefisso `ev*` e permesso `eventi`, modello: cruscotto delle Attivazioni del Polo Logistico, ma compilato dallo staff e senza link pubblici). `eventi.js` ha elenco a tabella, testata del cruscotto e Segnalazioni; qui stanno le schede Riepilogo, Volontari (con griglia `evento_disponibilita`), Mezzi e materiali, Ospiti e Cucina, l'Excel con ExcelJS caricato su richiesta e le liste `eventi_tipologie` / `eventi_esigenze` in Impostazioni. La configurazione dei campi è in `eventi.campi`; le abilitazioni arrivano da `formazione_registro`. Una riga in `evento_disponibilita` vuol dire disponibile; i conteggi sono calcolati nel browser e `evSalvaVolontario()` è l'unico punto di salvataggio, anche per l'import.
- `gestione-accessi.js` — pagina Gestione accessi in Amministrazione (prefisso `ga*`, solo `tipo_accesso` master, la sicurezza sta nelle regole di `staff` ed `email_accesso`): staff, mail di accesso, permessi con matrice, volontari senza mail. `GA_GRUPPI` è l'elenco delle chiavi di permesso: una chiave nuova va aggiunta lì. Registro accessi (permesso `accessi`) mostra solo i log.
- `bot-telegram.js` — lato app del bot Telegram (prefisso `bt*`, permesso `eventi`): link personale monouso (scheda volontario e Gestione accessi) e messaggi massivi (Eventi e Impostazioni), sempre tramite la Edge Function `bot-app`, che ricontrolla `ho_permesso('eventi')`. Il webhook è la Edge Function `bot-telegram`: verifica `TELEGRAM_WEBHOOK_SECRET` e riconosce il volontario dal numero di telefono (`request_contact`, `contact.user_id = from.id`) o dal link personale, ha il menu fisso (foto, posizione, bollettino ARPA da `_shared/arpa.ts`) e registra le foto in `evento_segnalazioni` con file nel bucket privato `segnalazioni`; senza emergenza o esercitazione IN CORSO la foto è generica (`evento_id` nullo, `supabase/bot_02_generiche.sql`) e si assegna da Eventi → Segnalazioni generiche. Ogni segnalazione avvisa lo staff su Telegram (`_shared/avvisi.ts`: staff attivo collegato al bot, permesso `eventi`). La Edge Function `bot-avvisi` (pg_cron ogni ora) avvisa i master se l'allerta ARPA non si aggiorna, falliscono attività cron, le segnalazioni restano da gestire oltre 24 ore o manca il backup; il backup settimanale è nello schema `backup` (`supabase/manutenzione_01_backup_avvisi.sql`). L'allerta ARPA automatica è la Edge Function `bot-allerta` (pg_cron dopo le 14, quando esce il bollettino; `supabase/bot_03_allerta_automatica.sql`): scrive ai volontari collegati quando il quadro cambia con almeno un giallo e quando rientra al verde, mai con dato non fresco; si sospende con la riga `allerta_sospesa` in `bot_avvisi_stato`. Tabelle in `supabase/bot_01_tabelle.sql`; quelle `telegram_*` del vecchio bot non si usano.
- `verifica-piattaforme.js` — pagina Verifica piattaforme in Amministrazione (prefisso `vp*`, permesso `aggiornamento_dati`): confronto annuale Portale / PIA / Volter. I file di PIA (`pia_volontari.json`, creato da `estrai-pia.js` nella console di PIA) e Volter si leggono solo nel browser (SheetJS caricato su richiesta); il confronto lo fa `verifica-piattaforme-core.js` (funzioni pure, non cambiarne la logica senza avvisare); le decisioni per persona e anno passano dalla Edge Function `vp-api` (`vp_dati`, `vp_leggi`, `vp_salva`, tabella `verifica_piattaforme`) tramite `aggCall(azione, dati, VP_API_URL)`. "Applica al portale" usa `agg-api update_anagrafica`; i dimessi vanno a DIMESSO anche in `volontari`.
- `accesso.js` — nuovo accesso con Google o codice via email (prefisso `au*`, Supabase Auth): sessione persistente, profilo dalla funzione SQL `mio_profilo`, token letto da `auToken()`.
- `belfiore-comuni.js` — static lookup data (Italian comuni / Belfiore codes) used for codice fiscale validation.
- `manifest.json`, `sw.js` — PWA manifest and service worker, scoped to `area-riservata.html` (cache name `pcana-vN`; bump the version when changing cached assets so old caches are evicted).
- `_headers` — Cloudflare/host header rules (currently disables content-encoding on `area-riservata.html`).
- `icons/`, `images/` — static assets.
- `guida/` — guida utenti pubblica, statica e separata dall'app (`pcanacasale.com/guida/`): `index.html` è il motore, `dati.js` i contenuti, `genera-audio.mjs` crea gli MP3 in `guida/audio/`. Il service worker non la intercetta. Vedi "Guida utenti".
- `et/` — unrelated one-off HTML fragments/pages (different branding, e.g. "ET Store", "Wind Tre"); not part of the ANA site, treat as independent standalone files.

## `area-riservata.js` architecture

This is a single-page app manually driven by DOM manipulation (no framework). Key structure:

- **Auth**: only Supabase Auth (Google or email code, see `accesso.js`); the old password/codice fiscale login is gone. `currentUser.tipo_accesso` is `'master'`, `'standard'`, or `'volontario'`; `canModificaVolontari()` and similar checks gate write actions client-side based on `tipo_accesso` / `permessi`. `SUPA_URL` and the `SUPA_KEY` anon key are hardcoded near the top of the file. Who has access lives in `staff` and `email_accesso` (names from `volontari`): the `utenti` table must not be read or written.
- **Files**: private buckets are listed in `SB_BUCKET_PRIVATI`. Save `sbPercorso(bucket, path)` (`bucket/path`), never a public URL; old rows still hold full URLs and `sbRif()` reads both. Use `sbFirmaRighe()` for lists, `sbLinkFile()` for links, `sbEliminaFile()` to delete. Volunteer photos are in the private `foto-volontari` bucket: sign `foto_url` with `sbFirmaRighe()` and draw them with `sbAvatar()`, which falls back to initials.
- **Navigation**: `showPanel(name, btn)` toggles `.panel` divs (each with id `panel<Name>`, defined in `area-riservata.html`) inside `.main-content`. Panels: Home, Volontari, Visite, Formazione, Convocazioni, Eventi, Interventi, Postazioni, Db, Accessi, GestioneAccessi, Schedapers, Segnalazioni, Galleria, Dotazioni, PianiCarico, Mezzi, Tlc, Statistiche, Richieste, Impostazioni.
- **Backend**: all data access is direct REST calls to Supabase (`SUPA_URL + '/rest/v1/<table>'`) made through `sbFetch()`, never plain `fetch`: it adds the session token (the anon key stays only in the `apikey` header, `H` / `HJ`), makes denied reads return `res.ok === false` with body `[]`, and warns on denied writes. In a loader use `sbOk(res)` inside the `try` so the section shows "Non disponibile." Home reads the views `volontari_pubblici` and `interventi_recenti`; `showPanel()` checks `PANEL_PERM` before loading a panel. Main tables: `staff`, `email_accesso`, `volontari`, `interventi` / `interventi_con_stato` (view) / `intervento_volontari`, `mezzi`, `postazioni` / `postazione_volontari`, `mappe_intervento`, `documenti` / `documenti_mezzi` / `documenti_tlc`, `tlc`, `dotazioni` / `dotazioni_categorie` / `dotazioni_magazzini` / `dotazioni_manutenzioni`, `piani_carico` / `piani_carico_mezzi` / `piani_carico_voci`, `log_attivita`, `log_accessi`, `richieste_adesione`, `segnalazioni`, `schema_volontari` / `viste_volontari` (custom-field schema and saved filter views for the volontari list).
- **AI integration**: `apriChatAgenteIntervento()` and related `aic*` functions call a Supabase Edge Function (`AGENTE_INT_URL`, `.../functions/v1/Agente-Interventi`) that turns a free-text message into a draft "intervento" record for confirmation; it requires the session token and the `interventi` permission.
- **PDF/export features**: attestati (certificates) are generated client-side (`_generaPDFBlob`, `_buildAttestatiHTML`) via a lazily-loaded library (`_caricaLibreriaAttestati`); Excel export/import for postazioni uses `pstEsportaExcel` / `pstImportaExcel`.
- **Maps**: postazioni can be placed on a static image map (canvas-based, `pst*Canvas*` / `pst*Immagine*` functions) or on Google Maps (`pst*Google*` functions, loaded on demand via `pstCaricaGoogleMapsScript`).
- **PWA**: registers `sw.js` on load; the service worker network-passes through requests to `supabase.co`, `teable.ai`, Google Fonts, and cdnjs, and otherwise falls back to cache on fetch failure.
- Naming convention: many related functions share a lowercase prefix per feature area (`pst*` = postazioni, `dot*` = dotazioni, `db*` = generic "database" panel, `tlc*`/`aic*` = their respective panels) — searching by prefix is the fastest way to find a feature's code.

## Working in this repo

- Prefer `Edit` over rewriting whole files — `area-riservata.js` and the larger HTML files are big enough that full reads/rewrites are wasteful; grep for the specific function/id first.
- Since there's no build step, any syntax error in the edited file breaks the page directly in production once deployed — double-check JS edits (e.g. with `node --check file.js`) before considering a change done.
- The Supabase anon key embedded in `area-riservata.js` is intentionally public (client-side anon key); do not treat its presence as a leaked secret, but also don't add any *service-role* keys or other credentials to this repo.

## Guida utenti

La guida pubblica in `guida/` va tenuta allineata all'app. Regole permanenti:

- Ogni modifica che cambia cosa vede o fa l'utente (nuova funzione, nuova sezione, pulsante rinominato, passaggio diverso, permessi cambiati) deve aggiornare anche `guida/dati.js` nella stessa sessione: testo del passo (`d`), copione parlato (`v`), `intro` della pagina se serve, e la schermata finta (`schermo`) se l'elemento citato non c'è più o è nuovo (i passi lo indicano con `h` = `data-h` della schermata). Una nuova voce di menu = una nuova pagina della guida, con il giusto `percorso` (`["volontari"]`, `["staff"]` o entrambi) e il suo posto in `GUIDA.percorsi.staff.ordine`.
- Stile dei testi: italiano semplice per volontari, niente tecnicismi. `d` = breve e asciutto; `v` = parlato colloquiale, come qualcuno che spiega seduto accanto, 2-4 frasi.
- Dopo aver modificato `dati.js`, rigenera solo gli audio cambiati con `node genera-audio.mjs --gemini` (da `guida/`, chiave dalla variabile utente `GEMINI_API_KEY`, mai scritta nei file). Mai usare `--forza` se non richiesto.
- Le modifiche puramente grafiche o interne (stile, refactoring, bug fix invisibili) NON richiedono di toccare la guida.
- Nel riepilogo finale di ogni lavoro scrivi sempre una riga "Guida: aggiornata (pagine X, N audio rigenerati)" oppure "Guida: nessuna modifica necessaria".
